# 插件新手指南：从换立绘到玩法插件

0.3.1 的特效接口需要编辑 JSON；步骤见文末「给插件干员加特效」。

这份指南写给**不会写代码、也不想碰命令行**的玩家：用浏览器里的「插件工作台」，几分钟就能把某个干员的立绘换成你自己画的，
和原版并排预览，打包成 zip 发给朋友。后面还有新干员、DSL、试一场、脚本、安装和批量删除的步骤。会用命令行的朋友，第二部分有同样事情的命令行做法。格式的完整说明在
[PLUGINS.md](PLUGINS.md)（英文，§9 外观插件、§15 工作台与工具）；让 AI 帮你做插件，请它先读 `plugins/AGENTS.md`。

> 外观插件只改画面和声音（头像、立绘、模型、图标、语音、音效、音乐），**不改任何数值和对局**：开了外观插件的对局仍然是原版对局。
> **不要把官方游戏的文件放进插件**——用自己画的、自己录的，或者「借用」本安装已有的素材（见下文）。

## 你需要什么

- 一台正在运行游戏服务器的电脑（自己电脑上 `npm start`，或者双击发布包里的启动脚本）。
- 浏览器（Chrome、Edge、Firefox、Safari 都行）。
- 你自己的图片：立绘建议 PNG 或 WebP，约 1024 × 1024，人物居中靠上；头像 180 × 180。

插件放在服务器的 `plugins/` 文件夹里，一个插件一个文件夹，文件夹名就是插件的 **id**。

## 做法一：用插件工作台（不写代码）

### 主题与公告（手写清单）

外观插件可以在 `plugin.json` 添加 `"permissions": ["theme"]` 和 `"theme": { "vars": { "--text-hi": "#f4faf7", "--t-fast": "0s" } }`。若还有素材权限，把 `theme` 加到原来的权限列表。只能写本安装的颜色、时间和缓动变量；完整名单在 `shared/plugins/theme.js`。颜色用十六进制或 `rgb()/rgba()/hsl()/hsla()` 的数字、百分比，时间为 0–2000ms 或 0–2s，缓动用 CSS 关键字或 x 在 0–1 的 `cubic-bezier()`。不收网址、`var()`、引号或 CSS 语句。[ASSUMED] 每个原始值最多 400 个字符（UTF-16 码元，包含首尾空白），服务器与客户端都在去空白和解析前检查。

任何类别的插件都可以添加 `"notices": [{ "id": "welcome", "title": "欢迎", "body": "第一行\n第二行", "date": "2026-10-17", "i18n": { "en": { "title": "Welcome", "body": "First line\nSecond line" } } }]`，不需要新增权限。日期与译文可以省略。服务器所有已加载插件的公告都会显示，与房间选择无关；标题页和大厅有公告时才出现入口，打开后清除未读点。[ASSUMED] 只显示纯文本，链接也是文字，每个插件最多 20 条，标题 80 字、正文 2000 字；全目录最多 100 条、48 KiB 的公告 JSON，按新到旧保留，遇到放不下的跳过这一条，继续保留后面放得下的公告，客户端也会独立执行这些上限。新增第一条、编辑或删除最后一条公告，以及修改主题值，都不改变 cs、vs 或房间使用的插件哈希。[ASSUMED] 清单始终去掉 notices/theme 后按规范 JSON 参与身份计算，锁文件仍按原始字节验证；外观锁只让已校验的 Spine 元数据参与外观身份，实际素材另行哈希。这会迁移旧版使用原始清单字节的插件哈希，包括未声明新字段的插件。只有公告的个人外观插件不显示开关、不请求空素材层，但会留在依赖查找中，其他外观插件可以依赖它。公告不影响对局。工作台的清单保存与命令行检查使用同一套校验；这一版没有专门的主题/公告表单。

### 1. 打开工作台

服务器启动后，窗口里会多一行 **`Studio:`**，后面是工作台的地址，形如 `http://localhost:3000/studio/#key=…`。
点开它（或复制到浏览器）。`#key=` 后面是**工作台钥匙**：新建、修改插件都要用它。浏览器会记住钥匙，以后直接打开
`http://localhost:3000/studio/` 就行。同一个局域网里的其他电脑：把地址里的 `localhost` 换成服务器的局域网地址（窗口里
`LAN:` 那一行）。如果打开的工作台顶部有一条「只能查看」的提示，说明这个浏览器还没有钥匙——把 `Studio:` 那一行的地址
粘贴进去点「使用」。钥匙也存在服务器的 `plugins/.studio-key` 文件里；删掉这个文件再重启服务器就会换一把新钥匙。

工作台**只对本机和局域网开放**：别人从公网访问只会看到「页面不存在」。如果你用 **TCP 方式的内网穿透**（frp 的 tcp
隧道、`ssh -R`、ngrok tcp 之类）把服务器开给公网，公网来的连接在服务器看来就像来自本机——这时别人没有钥匙，改不了你的
插件，但能看到工作台里的插件；不想被看到就用 `SP_STUDIO=off` 启动服务器（关掉工作台）。

（截图位置：工作台首页——左边是插件列表和「新建插件」按钮，右边是四步说明。生成方法见文末「截图从哪里来」，文件名 `studio-start.png`。）

### 2. 新建插件，选模板

点左上角的 **「新建插件」**，选模板 **「换头像 / 立绘 / 图标」**。其他外观模板分别是换 Spine 模型、换语音、换音乐 / 音效；玩法与界面模板见后面的章节。

（截图位置：新建插件的模板列表。`studio-templates.png`）

### 3. 按官方名字找到要换的干员

在搜索框里输入干员的**官方名字**，例如「德克萨斯」，点结果里带头像的那一项。不需要知道 `char_102_texas` 这种内部 id——
它只是小字显示在名字下面。敌人、召唤物、道具、盟约、策略和界面图也都能这样搜。

（截图位置：搜索「德克萨斯」的结果。`studio-picker.png`）

### 4. 起名字，创建

名字已经帮你填好（可以改）；**插件 id 会自动生成**一个合法而且没人用过的（2–32 个小写英文字母、数字或 `-`）。作者和许可证可以现在填，
也可以以后在「信息」里填。点 **「创建插件」**：服务器在 `plugins/<id>/` 里建好文件夹，写好 `plugin.json`（插件的清单）和一份说明。

### 5. 把立绘拖到格子上

插件页面左边是一个个**格子**：头像、精英二头像、立绘、精英二立绘。每个格子左边是原版，右边是你的插件。把你的立绘图片**拖到「立绘」格子上**
（或者点格子选文件）。工作台会把它放进插件文件夹里正确的位置（`art/char_102_texas/portrait.png`），同时更新清单。

右边是**实时预览**，用的是游戏自己的界面：商店和整备区里的卡片头像、点开干员时的详情卡（立绘就在这里），**原版和插件并排**。
换模型的模板还会显示游戏自己的战场画面，可以切换待机、移动、攻击、技能（S1–S3）、眩晕、倒下、部署每一个动作，正面和背面都能看。

（截图位置：拖入图片后的插件页——格子里是你的图，右边卡片头像和详情卡并排对比。`studio-preview.png`）

不想自己画？点格子下面的 **「用已有的素材」**，搜索另一个干员，就能借用他的立绘（不复制任何文件）。点 **「恢复原版」** 就清空这个格子。

### 6. 看提示，一键修复

如果哪里不对，格子下面会出现**白话提示**：出了什么问题、怎么改，下面折叠着英文原文。很多问题有 **「一键修复」** 按钮
（例如缺少权限、版本号写错、模型还没打包）。插件右上角的标签写着「已载入：可以在游戏里开启」就说明没问题了。

### 7. 填信息

在 **「信息」** 里填：名字、简介、版本（每次发布前调大，例如 1.0.1）、作者、**许可证**（别人能不能转发和修改你的作品，例如
`CC-BY-4.0` 表示署名即可转载）、**素材来源**（谁画的；用了别人的作品请写明出处）、主页，以及「谁能开启」（房主给整个房间开、玩家只给自己开）。

### 8. 打包并下载

点右上角 **「打包并下载」**：工作台生成 `plugin.lock.json`（每个文件的校验值，模型的动画数据），再检查一遍，然后下载
`<id>-<版本>.zip`。这个 zip 就是可以分享的插件。

（截图位置：打包完成的提示条。`studio-packed.png`）

### 9. 在游戏里开启

- **房主给整个房间开**：在房间顶部点「原版 / 插件 ×N」标签，打开插件面板，勾选你的插件。房间里所有人都会看到新立绘。
- **只给自己开**：设置 → 外观插件，打开开关（只影响你自己的浏览器）。

**热重载**：工作台打开期间，插件文件一改（工作台里拖了新图，或者你用画图软件直接保存到插件文件夹里），**几秒内游戏里就跟着变**——
仅含外观插件的房间里，如果你是房主（同一个浏览器里玩），或者房间里只有你一个人，会自动重新应用；其他房间提示房主「请点重新应用」。有玩法插件的房间始终由房主手动重新应用，对局中保持原来的内容。个人插件在下次重新获取插件列表后跟随。

## 做法二：用命令行

```bash
# 1. 从模板新建（目标按官方名字找）
node tools/plugin.mjs new art my-texas --target 德克萨斯 --name "我的德克萨斯" --author 你的名字

# 2. 把图片放进文件夹，在 plugins/my-texas/plugin.json 的 "assets" 里写上路径：
#    "assets": { "chars": { "char_102_texas": { "portrait": "art/char_102_texas/portrait.png" } } }

# 3. 检查：每个问题下面一行白话说明和改法（--lang en 是英文，--json 给编辑器和 AI 用）
node tools/plugin.mjs check my-texas

# 4. 打包：写 plugin.lock.json，再打成 zip（默认放在 plugins/_dist/my-texas-1.0.0.zip）
node tools/plugin.mjs pack my-texas --zip
```

`node tools/plugin.mjs new` 不带参数会列出所有模板。`plugin.json` 开头的 `"$schema": "../../schemas/plugin.schema.json"`
让 VS Code 这类编辑器自动补全字段、标出写错的地方。一次检查 `plugins/` 里的全部文件夹，或一次点名多个文件夹时，还会按
注册表的规则看跨插件的问题：重复的 id、同一种语言的第二个覆盖（提示里写明已经生效的是哪个插件，按文件夹名排序，第一个
胜出）、两个界面插件要同一个位置（警告 `PLUGIN_UI_SLOT_SHARED`：对局里用标签切换，一次只显示一个，不是失败）。只检查
一个文件夹时不扫其他文件夹。`plugin list` 和服务器读同一个 `SP_PLUGIN_SCRIPTS`：`sandbox` 且锁有效时脚本插件是已加载，
没设置或 `trusted` 但没钉住锁时仍是禁用。

界面插件的页面要在 `html` 上写 `color-scheme: dark`（模板已经写了），否则 iframe 会铺一块不透明的白底，浅色字读不清。
插件自己设置的背景仍会显示。对局右侧的位置在商店、手牌、准备按钮和资金旁边，不盖住它们。同一个位置有多个插件时，按
名字先显示一个，玩家用位置里的标签切换。

## 其他模板的要点

- **换 Spine 模型**：用 Spine 3.8 导出**二进制** `.skel`（不是 `.json` 骨骼），把 `.skel`、`.atlas` 和贴图 `.png` **一起**拖到
  「正面模型 / 背面模型」格子上。动画（待机、攻击、技能、倒下……）在打包时从模型里自动读出，不用手写；模型换了以后再打包一次。
- **换语音**：每一句语音一个格子（行动出发、行动开始、选中干员、部署、作战中 1–4、结算……，中文和日文配音分开）；一个格子放几个文件，
  游戏会轮流播放。每个格子都能点 ▶ 和原版对比着听。
- **换音乐 / 音效**：音乐分「循环部分」和只播一次的「前奏」（点「放入前奏」）；音效是 `.mp3` 或 `.ogg`；也能换某个干员自己的攻击、受击、技能声音。
- 一个插件可以同时换好几样：插件页下面的 **「添加替换内容」**，再选一个模板和目标（例如同一个干员的头像、模型和语音放在一个插件里）。

## 0.3.1 的外观模板

以下四项都在「新建插件」里，填写表单后点「保存修改」，再「打包并下载」。校验提示和服务器 / `plugin check`
共用读取器；数值越界、无效皮肤键或缺失绑定不会被自动截断。素材通过现有文件 / art / Spine 槽上传，
不新增服务端路由。重新打开时读取当前清单与记录；保存只合并表单修改，保留手写字段、额外声明和未修改的 JSON 原始字节。
表单保存要求完整目录连同素材通过严格检查，保留下来的无效内容也会阻止保存，并显示具体文件和原因。主题、公告和皮肤不需要玩法数据。
时装插槽上传和文件接口（PUT files/）上传采用「不新增问题」：按错误代码与文件位置比较上传前后的严格检查结果，可以逐张补齐多个缺图；每次上传的文件本身仍须有效。0.3.0 的图片、模型、语音、音乐插槽（以及盟约图标）照旧直接写入，写入后再显示检查结果。
候选目录硬链接未修改文件，只有本次写入的文件受 64 MiB 等单文件上传限制；已安装的大文件无需重新上传。总量仍为 200 MiB、5000 文件。
[ASSUMED] 暂存放在真实插件目录内、注册表忽略的 `.sp-studio-*` 隐藏目录；有符号链接（包括隐藏链接）时拒绝操作。
创建硬链接和完整检查在独立子进程中执行（最多同时 2 个、每个 20 秒、512 MiB 堆上限，[ASSUMED]），结束后清理；写入失败会回滚。

### theme — 主题变量

每个允许的设计令牌都有一行，显示本工作台的默认值：颜色选择器与颜色文字值、0–2000 毫秒时长、缓动枚举或
cubic-bezier 四个坐标（x 为 0–1，y 为有限数）。只保存修改过的项，每行「恢复默认」删除该项覆盖。
「在工作台上实时预览主题」直接改变当前工作台；离开编辑器、切换标签页或关掉预览会恢复原值 [ASSUMED]。
最多 64 项；不允许 URL、任意 CSS、字体或布局变量。插件为 personal 范围，需要 `theme` 权限，不改变房间玩法。

### notices — 插件公告

添加公告，填写唯一 id（1–32 位小写字母、数字、连字符）、标题（80 个 Unicode 字符以内）、正文（2000 字以内），
日期可留空或填有效的 YYYY-MM-DD。最多 20 条。勾选所需语言后分别填写完整标题和正文；切换「预览语言」检查
与游戏公告相同的语言回退。预览保留换行，HTML 和网址都作为纯文本显示，不执行、也不生成链接。
空的公告列表不会发布任何公告；只有公告的插件若清空全部内容，保存前就会提示插件为空，原文件保留。

### fx — 干员特效

模板创建一个借用官方技能的演示干员 [ASSUMED]，默认有一张原创 CC0 棋盘格 PNG，在演示干员默认装备技能的 attack 相位播放。
可用官方名字搜索更换「技能来源」，不用手写干员 id。演示干员保留来源的伤害类型和攻击信息；需要专属召唤物的来源（如令、傀影）暂不支持，表单会明确拒绝 [ASSUMED：紧凑记录格式的限制]。
演示干员是内容插件，正式使用时对局仍会标为非官方。

- **借用官方特效**：列表只含本机 `public/assets/local/fx/index.json` 中的角色，搜索并选择后，将本干员每个技能槽
  映射到该角色已有的官方技能，留「默认」则走原有回退。索引缺失时有提示；先手动提取官方特效，或改用序列帧。
  官方特效只在 3D 显示，不继承技能数值。
- **序列帧动画**：添加条目、选择 PNG，再一次保存图片与表单。图片读取期间「保存修改」不可用；先后选图和读取期间修改参数都会保留。填写帧数 1–256、列数 1–帧数、fps 0.1–60、锚点 x/y 0–1、
  缩放 0.01–8，选择 normal / add 与循环。PNG 为 8 位 RGB/RGBA，每边最多 2048 像素，宽高必须能整除格子。
  在列表里为每个技能选择 skillStart / skillLoop / skillEnd / attack / hit / projectile 与特效 id；重复槽位+相位或
  引用已删除的特效会被拒绝。[ASSUMED] 表单最多 128 个序列帧、60 行相位绑定（10 槽 × 6），每个地址只写一次。

打开「试一场」，使用插件的新干员，点「开始对照」。未保存的特效参数与已选图片也参与试战。试战与表单使用相同的 160 MiB 请求上限；
[ASSUMED] 回放内嵌暂存 PNG（压缩文件合计最多 8 MiB，整份结果仍限 16 MiB），临时目录删除后仍可播放。
检查 2D / 3D、暂停和重新播放，
序列帧两种棋盘都显示。「官方特效」关闭会一起隐藏。编译粒子索引仍按原文件接口编辑，本表单只创建官方借用和序列帧。

### skins — 干员时装

创建时用官方名字选干员，然后添加时装，填写皮肤键、名称和系列。键使用 `isSkinKey` 规则：1–64 字符，首字符为
字母、数字或下划线，其余允许字母、数字及 `_ @ # + . -`；每名干员最多 64 套，名称 1–64 字，系列 0–64 字。
保存后上传头像、立绘、正面 / 背面 Spine（与原模型模板一样，一次选 .skel、.atlas 与 PNG 页）。
皮肤键在磁盘目录中转为完整 UTF-8 十六进制 [ASSUMED]，带 @ / # / + 的不同键不会互相覆盖文件。
重命名后复用旧键，上传会为仍被别的皮肤引用的图片和整套 Spine 分配新目录，保留旧文件 [ASSUMED：数字后缀]。
皮肤插槽和文件 PUT 接口的上传先暂存并校验，错误不会替换原文件；Spine 用现有骨架 / 图集读取器检查并生成锁文件中的动作信息。
这些路径以及随特效表单暂存的 PNG 会校验签名、原始块名的 ASCII 字母、头部、各块校验和、调色板与结尾，并按编码的精确扫描行长度解压、检查过滤器；
支持普通 PNG 的所有合法色深 / 颜色类型与 Adam7 交错。[ASSUMED] 解压数据最多 256 MiB，防止小文件消耗过多内存。
只有声明为特效的贴图限定非交错 8 位 RGB/RGBA、每边不超过 2048；内联和外置 overlay 声明都识别。上传检查不区分扩展名大小写（`.PNG` 也按 PNG 校验）；特效贴图的路径仍须是小写 `.png`。
0.3.0 的美术 / 模型 / 语音 / 音频插槽和盟约图标仍直接写入，再显示检查结果，不经过上述素材校验。
皮肤插槽和文件 PUT 可以逐张修复缺图，但上传后的严格检查不得新增问题：错误码、位置和原因文字必须逐项完全相同，
且已有一条只能抵消一条。[ASSUMED] 原因中测量数值变化也算新问题，保守拒绝上传。
内容 JSON 的纯数据组合校验独立于素材错误运行，缺图不会掩盖新增的技能数值等玩法错误；表单保存仍要求整个合并目录通过。

预览按游戏选择器的同一 `availableSkins` 规则取图和回退，点击图片可放大；没有正面模型时标为「仅图片」，
不会误称可穿戴。清除素材后再改名称、重命名皮肤键或保存，不会把旧素材恢复。模板声明 `assets.add` 和
`assets.override`，兼容本机已有或其他内容插件提供的干员；只改外观，不改变内容哈希。详见 [SKINS.md](SKINS.md)。

## 分享和安装

- 把 zip 发给别人。对方把它**解压到服务器的 `plugins/` 文件夹**里（解压出来的文件夹名就是插件 id），不需要重启服务器，刷新页面就能在插件面板里看到。
- 工作台和打包工具**不会检查**插件里有没有官方游戏文件——这是作者自己的责任。请只分享你有权分享的东西，并在「信息」里写清楚许可证和素材来源。

## 做一个新干员

1. 打开带工作台钥匙的 `/studio/`，点「新建插件」→「新干员」。按官方名字选一个技能和属性的参考干员，例如德克萨斯。
2. 起插件名字，确认自动生成的 id，创建。向导会生成自己的 `char_x_…` id、普通卡 `_a` 和精锐卡 `_b`，不用手工配对。
3. 填干员名字、职业、分支、稀有度和商店阶级。展开「普通」「精锐」分别改生命、攻击、防御等属性。
4. 「技能来源」选「借用官方 kit」「JSON 技能规格」或「DSL 技能 / 天赋」。借官方 kit 时仍按官方名字选；官方 kit 修复后，这个插件也会跟随。
   JSON 规格只适合已经会写 JSON 的作者。DSL 可以直接用下拉框编辑。
5. 展开「借用本安装已有的素材」，按名字选模型和头像的来源。这里生成 `{ ref }`，不复制官方素材。
6. 点「保存修改」，查看校验结果，再到「试一场」比较。最后「打包并下载」。外部编辑器改过文件时，请先重新读取再保存，以免覆盖。

（截图位置：`test/e2e/out/studio-gameplay-operator.png`，展示普通/精锐属性、官方 kit 来源和借用素材。）

命令行也可以：`node tools/plugin.mjs new operator my-operator --target 德克萨斯`。进阶参数放进一个 JSON 文件，
使用 `--options 文件名`，与工作台向导的 `options` 字段相同。随后运行 `check my-operator --strict`、`pack my-operator --zip`。

## 写一段 DSL 天赋

1. 新建「DSL 技能 / 天赋」。默认是一个被动攻击力提升 50% 的术师，附第 1 回合收入为 15 的备战文件；也可从地灵、隐现、德克萨斯、风丸、老鲤五个例子中选起点。老鲤是备战效果，其他四个生成可上场的新干员。
2. 在「天赋」点「添加触发规则」，选择「部署时」。在「条件」里按需选触发概率、生命比例或盟约条件。
3. 点「添加动作」，选「增加属性」→「攻击力比例」，把取值选为数字并填 `0.5`。也可以选择技能黑板、天赋黑板、单位实时属性，
   或用加减乘除组合取值。目标可以选自身、当前目标、范围内友方/敌人等。
4. 右侧/下方会显示同一套 `validateDsl` 的白话检查结果。按提示修正，直到「DSL 校验通过」，再保存和试跑。
5. 备战规则用「备战效果」模板：回合开始、收入、购买等触发器，配资金、盟约层数或道具动作。

风丸例子没有「技能结束时收回替身」这个 DSL 动作，适合 20 秒以内对照；完整限制见 [PLUGIN-DSL.md](PLUGIN-DSL.md) §7。
工作台生成 `kit: { dsl: … }`（战斗）或清单 `dsl: ["dsl/meta.json"]`（备战）以及 `dsl` 权限。
保存会重新校验当前规格，规格被拒绝时不会写入文件。校验请求失败时会明确提示，可以重试。整体检查与试跑还会核对内容组合的权限、引用和数值上限。

（截图位置：新干员向导中选择 DSL，展开触发器、条件和动作；浏览器验收后可保存为 `test/e2e/out/studio-gameplay-dsl.png`。）

## 试一场

0.3.1 的五个玩法表单见下文；它们还提供「玩法试验」，可以单独触发准备事件和操作交互窗口。

1. 在插件列表选一个插件，打开「试一场」。在向导里尚未保存的修改也会作为临时草稿试跑，磁盘文件不会因此改动。
2. 选择「单干员对木桩」「对一波敌人」或「两名干员对打（定点攻击试验）」。源代码安装还可以选择 golden 中的战斗场景。
   默认优先派插件新增的干员；也可另选官方干员、对手和波次。普通预设的时长为 1–120 秒。
3. 点「开始对照」。服务器先校验插件并构建内容组合，错误会直接说明原因，不执行坏插件。脚本插件仍遵守服主开关和锁文件哈希许可。
4. 查看原版/插件的伤害、时长、结果和差值；新干员用所借用的官方干员作原版参照，参照名字显示在表里。
   两边回放都使用游戏自己的战场渲染器，可以暂停、重播和改变速度；「事件摘要与伤害统计」显示真实模拟结果。
5. 调整数值后再试。木桩是不会移动和攻击的高生命测试目标；定点对打是通过引擎攻击接口做的试验，敌人专用技能不会把另一个干员当敌人，
   不能据此判断正式 PvP 平衡。备战经济的完整流程需要放进实际房间验证；五个新模板可单独派发一次准备事件，其他模板仍只运行战斗。

每次对照在独立子进程中完成，默认最多同时 2 次、每次最多 20 秒墙钟时间。超时、崩溃或回放太大都有白话提示。
浏览器只播放快照与事件，不执行插件战斗脚本。只有本机/局域网带工作台钥匙的请求能启动。

（截图位置：`test/e2e/out/studio-gameplay-trial.png`，并排比较表与两侧回放。）

其他玩法模板：「改数值」展示原版属性/黑板字段和上限（黑板同键原版最大值的 10 倍，至少 64，正数步长下限显示在字段旁，非法值不能保存）；「新模式」继承官方模式并改经济和时长；
「界面小组件」选插槽、改标题，保存后用真实 `pluginFrame` 宿主播放假数据；「脚本插件」生成 SDK 骨架及 `test/` 测试，浏览器带钥匙时可只读查看，试跑沿用服主选择的沙箱或受信任模式。
请用编辑器打开插件文件夹，运行 `node tools/plugin.mjs test <id>`。

房间的插件面板现在会按清单显示布尔/整数/小数/枚举设置。房主点「应用设置」后，所有玩家会重新加载同一个内容组合。
其他玩家只读；正在对局时不能改。修改自动依赖插件的设置会把该插件变为显式选择。内容文件变动时只提示房主重新应用，运行中的对局保持旧内容。

## 0.3.1 玩法模板（不用手写 JSON）

每个表单都会实时调用服务器的插件校验与组合检查；输入越界会显示错误，保存时再次检查，不写入坏草稿。
按官方名字搜索目标，列表用「添加」「删除」编辑。修改后可以直接「试一场」，不必先保存；需要改图标时先保存表单。
重新打开时从当前 JSON 读取表单字段；保存只更新表单改动的字段。手写的其他字段、额外记录、声明、权限和素材都会保留，未改动的 JSON 文本保留原始字节。实时校验、保存与未保存试战共用完整合并结果；包括保留文件和必需依赖的检查失败时，不写任何文件。

### 新盟约（bond）

填写名字、描述、递增门槛（1–16 个，每个 1–100）、计数方式和核心开关；添加官方干员成员（最多 64 个）。
BOARD 只数场上，BOARD_AND_DECK 包括手牌，BOARD_ALL_CHESS 数精锐（含重复）。选「效果所需层级」，
然后用原有 DSL 表单填写准备效果（资金、层数、道具）和成员天赋。层数目标可直接选「本插件盟约」。
生成器自动加上本盟约激活条件，不覆盖原干员技能。图标插槽可上传自己的 PNG/JPG/WebP 或借用官方盟约图标。
默认原创 CC0 棋盘格可替换。[ASSUMED] 一个层级控制所有规则；试战直接激活这个层级，默认使用第一个成员，
显示战斗伤害和准备资金变化。触发器包括 income、refresh；特质模板则使用 gain、deploy 等自己的八个钩子。
[ASSUMED]「自动」选择草稿的第一条准备规则，无准备规则时选 roundStart；income 从零收入开始，setIncome 的结果会实际入账。人口计数仍要在正式测试房间验证。

### 新道具（item）

搜索官方基础道具，选择是否生成普通／精锐配对，分别填写价格、阶级、描述及已有 buff 的黑板数值。
价格为 0–1e9，阶级 1–6；黑板输入显示官方校验上限。商店隐藏、排除商店与排序分别可调。
配对沿用基础道具的合成数量和效果处理器，不创造未实现的 buff。MAGIC 和没有 buff 的变形道具也可作为基础；没有精锐形态时禁用配对。
每次生成按最终 buffs 重算 params：同一 buff 的字符串值优先于数值，多条 buff 同键取第一条，与现有数据构建规则一致。[ASSUMED] 试战将选择的普通／精锐装备装到第一个干员；
非装备道具只进入试验库存，消耗品与陷阱的使用目标需在房间测试。

### 干员特质（trait）

搜索干员，填写必填的中文特质文本及可选的四种译文。默认追加特质；只有勾选「明确替换官方特质」才替换模式特质，
职业特性、技能、模组和原有天赋仍保留。战斗规则的 elementBurst 可选五种元素和 targetOnField/selfOnField 条件；
层数动作可以选择自身激活的盟约、设置每场上限（1–1000000）。准备规则包含 gain、deploy、roundStart、buy、sell、merge、levelUp、battleResult，
获得道具的数量为 1–64。表单的共同规格应用到普通和精锐形态。[ASSUMED] 玩法试验向第一个持有者派发一个选定事件，
可查看库存、资金和层数变化；木桩不会主动造成元素爆发，需要相应敌人波次或测试房间验证爆发规则。
[ASSUMED] 独立盟约／特质模板只接受本安装已有可上场棋子记录的官方干员；仅有补位资料的干员应先制作干员插件，
单独的特质声明不会创建普通／精锐棋子，因此表单会提示引用错误。

### 交互窗口（offers）

选 prep／battleCheck 时机和回合条件（任意、逐项、每 N 回合、范围），填写 1–6 个显示选项、每格 0–2 次刷新和窗口秒数。
0 秒不打开窗口；none 不阻塞流程，all 等全部，majority 等多数；可选超时处理和延后准备结算。
在选项池逐条填写标识、名字、描述、图标和奖励（资金、待结算资金、免费刷新、层数、道具、干员）；池至少有显示数量那么多张、最多 128 张。
文件由模板生成。在「试一场」的玩法试验选择会命中的回合、时机，点「开始对照」，再点选择／刷新／推进到超时。
这里调用真正的 Match 窗口逻辑，展示阻塞状态和奖励前后对比。[ASSUMED] 单席、固定种子、最多重放 32 个操作，不创建房间。

### 规则开关（rules）

四个下拉框分别选择 shopBias（official／bondBias）、prepLoadout（locked／prep）、morphPairing（official／plus）、
unequip（official／allow）；每项下面显示作用说明。选「继承」不声明该项；显式默认值也会进入内容身份。
[ASSUMED] 至少保留一个声明，避免生成完全空白的规则插件。
玩法试验逐项显示原版和插件的真实 Match 操作结果。[ASSUMED] 固定场景为：放置足够的维多利亚成员后在一级商店免费刷新 12 次；
准备阶段将首名干员技能设为 0；依次装备两件盟约装备和变形同构体；另一个持有者尝试卸下精锐锤子。
回放携带实际装备、技能选择及 morphPairing 规则。完整经济、多回合及任意组合仍需测试房间。

以上五种模板的「玩法试验」只附加到木桩、波次和对打预设，不改变 golden 场景或独立的原版测试控制台。
默认示例与单事件场景是 [ASSUMED] 的创作起点，不是官方平衡规则。

## 测试控制台

从工作台顶栏打开「测试控制台」（`/studio/console.html`），使用同一把钥匙，不用先选插件。服务器校验场景，
浏览器运行原版模拟和 3D / 2D 战场，不创建房间、不记录战绩。

1. 选地图、战场区域（各自行动 / 最终攻势 / 隐秘核心 / 联防）、难度、回合和种子。切换地图或区域会清空部署。
2. 按中文名或 ID 找普通 / 精锐干员，选技能、模组、两件装备和朝向，点击左侧部署格或实景棋盘。棋盘一开始停在部署动作之后（约 0.5 秒，[ASSUMED] 这半秒里敌人可能略微移动），干员以站立姿态显示，朝向可以直接看；开始或步进之前仍可放置，之后要重开场景再放。切换页面语言会刷新干员、盟约、地图和装置的名字。
   已部署单位点选后可改配置、移除；召唤物从「通过所属干员部署召唤物」选择。联防和领袖战可添加第二阵地。
   场地装置只能在官方预设位置开关；非法地格、召唤物距离和数量会报错，修正后才可开始。
3. 使用回合的官方波次，或添加自定义敌人的数量、出现时间、间隔和出生路线；领袖跟随所选领袖模板，悬赏精英
   可另加。盟约按手动设置的阶数、层数生效；策略及机变只运行战斗部分，不运行整备经济。
4. 「开始 / 暂停」「步进一帧」（1/30 秒）、「步进一秒」、0.25×–8×和「同种子重启」帮助复现问题。
   点击单位查看属性、HP、SP、增益和统计；切换官方特效关 / 精简 / 完整，查看伤害、治疗和本视图的特效日志。
   官方特效需要 3D 和安装好的本地素材；画面下方报告实际状态。切到后台会暂停，回来需手动开始。

对局里去改状态。

完整对局用大厅里的测试房间，默认关着。服主用 `SP_TEST_MODE=1` 或 `scripts/start.sh --test-mode 1` 打开。
默认的 `::` / `0.0.0.0` 在这台机器的网卡都是局域网时会开；有公网地址，或监听地址本身是公网，必须用 `force`，启动时用中文说明原因。认不出的取值保持关闭并警告。欢迎消息带 `testMode` 时，建房框多一个「测试房间」。作战进行中不能开关计时。
只有房主能建，也只有房主能在局内的测试面板里改资金、发棋子 / 装备 / 召唤物、改目标生命、跳回合或阶段、

房间、顶栏、观战和结算都标「测试」。测试结果和退出不写本机记录、不授予称号或奖励，也不算进统计、成就、徽章和卫戍认证。
普通房间没有这个面板，也不能中途改成测试房。

## 从 Forge 包导入

如果你有一份 Forge 工坊包（一个带 `pack.json` 的文件夹，或它打出来的 zip），可以把对得上的部分导成我们的插件。

在工作台里点 **「从 Forge 包导入」**。选一个 zip，或选整个文件夹。先看导入报告，确认之后才会写入 `plugins/`。
报告里写着导入了什么、改成了什么、没导入的和原因。常见的没导入原因：这是服务端逻辑、会改协议、是一段对不上的脚本
（导入器**不运行**包里的任何代码），或者挂载点对不上我们的界面插槽。

整条玩法记录没有写入时（干员 / 棋子、盟约、乐队、道具、召唤物、特性、技能脚本、面板），报告开头有「没有导入的玩法」，
JSON 里写 `partial: true` 和各类的 `dropped` 数量。`ok` 仍表示没有硬错误。外观要套的干员、棋子或道具全都没导入时，
这份产品写明没有可应用的对象；文件仍会复制。只替换一部分、或只有语音时，不写这句话。[ASSUMED] 效果不单列；棋子对已经
覆盖的干员、`--no-scripts` 不单独算进 `partial`。只生成骨架的面板算丢失一块面板，已复制的面板不计入丢失数量。
服务端模块、宿主样式或消息声明没有导入时，也会在开头写「部分导入 / Partial import」和「需要人工适配 / Needs manual adaptation」，
JSON 写 `partial: true`、`needsManualAdaptation: true` 和双语原因 `manualReasons`；`ok` 只表示校验通过。[ASSUMED]

### 导入与显示修复（0.3.1，§34.27）

「没有可应用的对象」按实际美术键判断：棋子用 `charId`，道具用 trap / icon 键，盟约用自身 id。
有保留下来的记录共用该美术键时仍可应用，不会因为另一个棋子或脚本被跳过而误报。[ASSUMED]
`assets` 声明的 `.spresources` 引擎资源容器仍需人工适配；即使没有生成插件，报告也写明部分导入与双语原因。

同次导入生成的内容插件用现有 `optional` 字段记录配套外观和版本。[ASSUMED] 房间启用内容后，若配套外观已安装、
版本匹配且自己与房间都没启用，插件面板显示「外观在『…』（设置 → 外观插件）」。它只提示，个人外观仍由自己开关。
规则冲突提示会写出两个插件名与当前语言的开关名。结算页的 Forge 宽表可以在 iframe 内横向滚动，窄面板宽度不变。[ASSUMED]

干员记录里的 `kit.dsl` 同样需要 `dsl` 权限；检查和注册表会识别它，工作台不会用旧的「未使用权限」一键修复删掉它。
特质 DSL 与官方特质覆盖所需的 `data.patch` 也保留同样的保护。

命令行做同一件事：

```bash
node tools/plugin.mjs import-forge <工坊包目录或 zip> [--out plugins/<id>] [--id <id>] [--dry-run] [--json] [--no-scripts] [--offline] [--asset-source=direct|mirror] [--refresh-index]
```

`--dry-run` 不写插件和报告文件，但可能缓存需要的官方表；加 `--offline` 可禁止下载。皮肤、立绘、头像、图标、Spine、语音、对得上的音乐和音效会变成外观插件；数值改动、
新干员、`chess.json` 里成对的新棋子（`_a` 普通、`_b` 精锐；`isDiy` 的六星写成自选）和新敌人会变成数据插件；界面词条
会变成语言包；公告和鸣谢仍写进清单的说明，并且各成一条公告（见下）。对不上的部分留在 `IMPORT-REPORT.md` 里，中文和英文各一行。

主题变量和公告：

- 工坊包的 `client.theme.vars` 会变成外观插件的 `theme.vars`。只能用本安装 `:root` 上的颜色、时间和缓动变量（例如 `--text-hi`、`--t-fast`、`--ease-out`）。对不上的名字会在报告里点名并且不写入。一个插件最多 64 个，每个原始值最多 400 字符。[ASSUMED] 玩家在「外观插件」里打开它之后，只改自己这个浏览器的界面，不注入样式表，也不影响别人。两个都打开时，插件 id 靠后的那个生效，面板上写着是谁的值。关掉立刻恢复。
- 只有主题、没有素材的包会变成一份只给个人用的外观插件（例如夜间主题）。带素材的外观仍是房间和个人都能选；主题仍只跟这名玩家自己的开关走。
- `notices.announcement`（或 `announcements`）和 `notices.credits` 会变成清单里的 `notices`。公告标题是版本、日期和摘要，正文是各节的名字和条目，一行一条；鸣谢单独一条，链接当普通文字。[ASSUMED] 纯文本，不解析 HTML。一个插件最多 20 条，标题 80 字，正文 2000 字。只有公告的包也会变成一份个人外观插件。公告不进内容哈希，不进房间，也不进对局。
- 关掉动画的面板和样式表（例如一份「轻量」包里的 `root.overlays` 面板）不会导入，报告写需要人工适配。它的主题变量仍会导入。

只读的 Forge 面板，如果脚本和包内的 `./` 引用都是 `.js` / `.css` / `.json`，并且静态扫描只碰到兼容层能提供的接口
（房间座位、结算统计、连接状态、协议版本和本房插件名单、面板自己的词条），会复制进界面插件：入口页在沙箱 iframe 里
加载兼容层再挂上面板。导入时仍然不执行脚本。`fetch`、`net.send`、包消息、改宿主页面的样式、外观提供者，报告会点名，
页面保持原来的骨架。[ASSUMED] 单个文件 256 KB，一个面板一共 1 MB、最多 64 个文件。`root.guide` 上监听 `room.state`
的面板显示在房间屏；其他对得上的未映射挂载点用建议插槽，那不是 Forge 原来的位置。同一个插槽有多块时，对局里用标签切换。

面板只接收父窗口的 feed，兄弟 iframe 发来的消息在排队前就会丢弃。每次入口文档只初始化一次，重复 `ready` 不会重发；
连接更新按每块面板独立去重、每秒最多一次，装另一块面板不会吞掉待发更新。[ASSUMED] 本房真实 `content.cs` 的前 8 位
作为 `net.welcome().mods.digest`；换房会替换，离房会清空，不编造摘要。静态或字面量动态导入 `/shared/i18n.js` 可使用 `t`，
静态导入支持别名和命名空间，其他静态导出会拒绝。`styles` 只能指向 `.css`，CSS / JSON 与入口都计入 64 个唯一文件上限。

依赖宿主 URL、桌面桥或宿主调用全局控制器的面板暂需人工适配：演示包的 guest-strip、lan-panel、match-overlay 都缺少
启动输入，不会作为兼容面板复制。[ASSUMED] 本服固定四席，没有容量设置；capacity-panel 的扩容字段 `playerCapacity` /
`seatCap` 会被点名为 `room.capacity`，暂不展示其 8/12/16/20 档位与房间设置提示。

技能怎么办：

- 干员或棋子的技能 id 全是**同一名官方干员**的官方技能时，记录保留这些 id，直接用那名干员在本游戏里的 kit（克莱门莎这类
  自选干员用她的自选 kit，棋子用对应官方棋子的 kit）。只对上一部分，或者对上好几名干员，就用通用 kit，报告写明原因。
- 包里的 `kits/<棋子 id>.js` 行为脚本会合成一个**脚本插件** `kits-<id>`：每个文件一个作用域，`@kit/tier1.js`、
  `@sim/constants.js`、`@sim/detmath.js` 改成 `sp:sdk@1`，包里 `./` 开头的文件一起带上。别的 import（`@kit/tier3.js`、
  `@sim/targeting.js` 的 `sortEnemyTargets` 之类）映射不过来，那份脚本就不写，报告里点名。导入时**不执行**它。
- 这个脚本插件**只在服主设置 `SP_PLUGIN_SCRIPTS=sandbox`（或受信任模式）并且房间选中它时**才运行（SES 沙箱，见下一节）。
  没开脚本的服务器照样能用数据插件，只是那名干员用通用 kit（或官方 kit）。
- 不想要脚本插件：命令行加 `--no-scripts`，或在工作台里勾选「不生成脚本插件」。
- 写 kit 的作者注意：天赋的 `install` 里加 buff 要写 `allowDead: true`（常驻的再加 `persist: true`，和 `kit.statBuff` 一样）。
  开战前干员还没部署，没写的 buff 会被引擎拒掉（Forge 的引擎也是这条规则）。报告会点名这样的 kit；Forge 自带的
  `kit-demo` 示例就是一例，导入后它的「攻击力 +25%」不生效。

覆盖一条官方记录时，还有这几条：

- `bonds` 里本安装没有的盟约 id 会点名，并且不写进名单。写进去的名单如果少了官方盟约，这份棋子会从那条盟约的 members 和 visibleMembers 里去掉；多了一条本安装已有的盟约，就加进去。报告点名这些官方 id。过滤之后一个都不剩时，官方 bonds 和成员名单都保持原样。
- 数组叶子（例如 rangeGrid）里有一个超出 ±1e9 的有限数时，整段数组不写，报告点名这条路径。同一条记录上的其他字段（例如 price）仍会导入。
- 只写了 `skill` 的一部分、没有 `skills[]` 时，按字段叠到官方技能上（对象合并，数组替换），并写回默认的 `skills[]` 条目。不会拿半份对象换掉整条技能。
- 官方驻守的 `bbStr.bond` 和 `bbStr.bond_id` 按逗号拆开。有一个记号不是盟约 id 时，点名，并且这个字段整段不写（不写成删掉未知记号之后的短名单）。记号全都是已有盟约时，改变后的字符串仍会写入。

Spine 骨架在导入和 `plugin.mjs pack` 里用同一次读取。骨头、插槽、皮肤、顶点的数量超过上限时，在分配数组之前拒绝：骨头、插槽、皮肤和顶点 4096，浮点数组 8192，三角形索引 16384。这些上限高于本安装实测的最大骨架（581 根骨头、360 个插槽、3 张皮肤、186 个顶点），也远低于 2^24。[ASSUMED]

完整对照表在 [PLUGINS.md](PLUGINS.md) §16。

## 开启脚本插件

「脚本插件」模板会生成示例技能和作者测试。用编辑器修改后运行：

```bash
node tools/plugin.mjs check my-script --strict
node tools/plugin.mjs pack my-script
node tools/plugin.mjs test my-script
```

`test` 会在本机执行作者的测试代码，不受服务器沙箱开关和受信任哈希许可限制；它不是生产环境的安全检查。
正式房间默认不开脚本。服主设置 `SP_PLUGIN_SCRIPTS=sandbox` 后（也可以启动时加 `--scripts sandbox`，Windows 上直接
双击 `scripts\start-windows-sandbox.bat`），`script` 类在 SES 沙箱中运行，浏览器用 Worker，服务器用受限子进程；要求锁文件与全部文件一致，不要求每位玩家逐个同意，也允许公网监听。修改文件后需重新打包。

`trusted` / `trusted-force` 是原生受信任执行：服主审查文件后，在 `plugins/config.json` 的 `trusted` 中填写锁文件
SHA-256，每位在座玩家也要同意。公网、`0.0.0.0` / `::` 通配监听或公网反代需 `trusted-force`。
第一次应用未缓存的脚本时，每个插件最多探测 5 秒，可能让大厅短暂停顿；`SP_SCRIPT_PROBE_MS` 可调整。
详细限制见 [PLUGINS.md](PLUGINS.md) §13 和[部署指南](DEPLOY.md)。数据插件里的 DSL 不需要开启这个开关。

## 按地址或社区目录安装

工作台点 **「从目录安装」**，填社区提供的目录 HTTPS 地址，或选择本机的目录 JSON 文件，查看版本和兼容性再安装。
目录里的每个下载都带 zip 的 SHA-256，由服务器下载并校验。项目不托管这些插件。

命令行也能安装本地 zip、按地址下载或查看目录：

```bash
node tools/plugin.mjs install ./my-skin-1.0.0.zip
node tools/plugin.mjs install https://example.invalid/my-skin.zip --sha256 <发布者提供的64位哈希>
node tools/plugin.mjs catalog ./catalog.json
```

示例域名不可下载，请换成发布者给的地址。远程下载默认只接受公网 HTTPS 的 443 端口。
同名插件默认不覆盖；需要替换时加 `--force`，旧目录会移到 `plugins/_replaced/`，不会删除。
安装检查不执行包里的代码；安装脚本插件也不代表它已经获准运行。完整规则见 [PLUGINS.md](PLUGINS.md) §17。

## 一次删除好几个插件

工作台左边的插件列表里，每个插件前面有一个**勾选框**。勾上不要的插件（「全选」一次勾上全部，「清除选择」全部取消），再点
**「删除所选（N）」**。确认框会列出这些插件的名字和 id；点「删除」后，它们的文件夹被移到服务器的 `plugins/_removed/` 文件夹里，
**不会被彻底删掉**：文件夹名后面加上了删除的时间，例如 `my-texas-20261015-083000-123`。想恢复某个插件，就把它的文件夹从
`plugins/_removed/` 移回 `plugins/`，把名字改回插件 id（去掉后面的时间），刷新页面就又能看到它。确定不要了，再自己清空
`plugins/_removed/`。

**正在使用的插件不会被删除**：某个房间开着它（正在对局也算）时，它留在原处，工作台会列出它和原因（带房间号），勾选也会保留；
等房间解散，或者房主在房间的插件面板里关掉它以后再删。符号链接的插件文件夹不能勾选，工作台不会移动它。玩家在自己浏览器里开的
外观插件和界面插件（设置里的开关）不算正在使用：删掉以后，它在那位玩家的浏览器里不再生效，恢复后又会生效。

### Forge 新棋子的附加信息（0.3.1）

紧凑干员可写 `chess.hidden: true`（保留供效果授予，不进商店、图鉴或自选池），
`chess.ids: { normal, elite }`（两个不同的本插件命名空间 id，不能同时写 `chess.id`），
`art.assets`（avatar/portrait/spine/voice/skillIcon/subProfIcon；加 Golden 指定精锐），

### Forge 导入后继续适配（0.3.1）

- 安全几何函数可以直接导入：`@sim/dir.js` 的 `dirVec`、`offsetTile`，`@sim/targeting.js` 的 `absoluteRangeKeys`。
  它们对应 SDK `sp.dir`、`sp.targeting`，返回冻结数组。`sortEnemyTargets` 会修改候选列表并读取战场对象，仍不开放。
- 内置语言也能装 lang 插件：[ASSUMED] 同语言只收一个覆盖包（文件夹排序决定），只改提供的词条，缺失词条回退内置。
  仍由每个浏览器选语言，不跟房间走、不影响战斗。原文 zh 不作为语言包。
- 界面包的 `PLUGIN_FORGE_MOUNT` 表示挂载点需要人工适配；`PLUGIN_FORGE_PANEL_SCRIPT` 表示面板脚本没复制。
  报告会写面板名、原挂载点和建议插槽；建议不是自动映射。只读且依赖都在包内的面板会复制进沙箱 iframe，不再报「没有复制」，导入时仍然不执行脚本。全部九种挂载点见 [PLUGINS §16](PLUGINS.md#16-forge-import)。
- 外观模板自带原创 CC0 棋盘格 PNG 和短音 OGG。工作台新建美术/音频模板时，目标的第一个插槽会填入示例 [ASSUMED]；可直接替换后校验、打包。


### 0.3.1：新盟约、完整装备与名单外官方干员

内容插件的 `data` 文件可以写新盟约：

```json
{"records":1,"entries":[{"file":"bonds","id":"bond_x_my_pack_team","value":{"name":"演示盟约","desc":"由插件 DSL 定义效果","thresholds":[2,4],"countMode":"BOARD","isCore":true,"identifier":30}}]}
```

插件 id 为 `my-pack` 时命名空间是 `my_pack`；不能占用官方或别的插件的盟约 id。阈值为递增正整数，
最多 16 档且每档不超过 100 [ASSUMED]。`BOARD` 数场上不同干员，`BOARD_AND_DECK` 加上手牌，
`BOARD_ALL_CHESS` 数场上所有精锐（包括重复）。成员由棋子的 `bonds` 生成，层数沿用原有持久状态和上限；
盟约条、详情、商店和机器人直接读取它。徽记用外观插件的 `art.bonds`。

名字、说明和黑板本身不产生新效果 [ASSUMED]。备战可用 `dsl` 文件的 `meta.on`，以
`if: { "bondActive": "bond_x_my_pack_team" }` 限制资金、层数和道具奖励；战斗效果写成员的 DSL 天赋或沙箱 kit。
完整装备记录可以保留普通/进阶两档、合成关系和商店参数，但只能使用引擎已有的 buff 处理器。
策略仍需官方 `base` / `effectRef`。召唤物记录不等于召唤行为；需要技能使用它。
干员形态可携带 `tags` / `tokens`（最多 64 个字符串 [ASSUMED]，召唤物 id 必须存在）。
自选召唤物优先使用唯一匹配练度的变体；没有练度匹配时，使用该形态棋子 id 对应的普通/精锐变体。

## 给插件干员加特效（0.3.1）

名单外的官方干员也能使用本机游戏里的美术：安装插件后运行 `node tools/setup.mjs --local`，
会提取这些引用的普通 / 精二头像、半身像和战斗模型的正反面。商店、详情、自选与棋盘都能使用，
插件自己带的图片和模型仍优先。启动 / 更新发现新增引用或丢失文件会询问是否重新提取，默认不提取；
明确输入 yes、`--local` 或 `--yes` 才授权，`--check` / `--no-local` 不提取。
完整提取前也先确认这项授权，普通本机素材的默认「是」不包含插件干员美术。直接运行 `extract.py`
时，完整提取须加 `--plugin-art`，也可显式选择 `--only plugin-art`。
只接受缓存官方角色表中存在的 id；官方表缺失或无法读取时不发现新引用。[ASSUMED] 去重、排除原版名单后，
按 id 排序，每次最多提取 256 名不同干员，Python 规划器也独立限制。单张图片读取、解码或写入失败会记录日志，继续处理同包后续图片。
新增 / 覆盖素材的权限仍按原始 `data/assets.json` 判断，引用则按合并后的清单解析；提取不会让原有 `assets.add` 插件突然需要 `assets.override`。
没有本机客户端、没有对应资源或跳过提取时，插件自带美术照常显示，否则仍可能缺图或使用通用棋子标记。
提取后重启服务并刷新页面。不会下载官方美术，也不额外提取时装、完整立绘、语音或改动玩法数据。
[ASSUMED] 已有安装素材的同名槽位优先，部分提取保留先前成功的槽位；检测要求基础图片与正反面模型，
缓存官方表声明有精二时也检查精二图片。文件只写入忽略的本地美术目录，具体路径和隔离提取见 [ASSETS.md](ASSETS.md#official-operator-art-referenced-by-plugins-031)。

借用官方特效，在干员 JSON 顶层写 `"fx":{"unit":"char_112_siege","skills":{"0":"skchr_siege_3"}}`。
这里的 `0` 是本插件技能的第一个槽位，右边是要借用的官方技能。它只决定画面，不继承数值、技能逻辑或模型。
`unit` 必须精确匹配本地索引；缺失时整个 `skills` 映射失效，回到原来的解析链，不去掉数字后缀猜干员。
[ASSUMED] 借用天赋画面只选本干员已装备的天赋序号和特性，模组画面仍要求对应模组启用。
工作台校验发现本机索引没有这个干员会警告；可以运行 `node tools/setup.mjs --local`，从本机游戏提取。
日常启动 / 更新发现插件新增引用，也会询问是否提取；默认不提取，明确输入 yes 才继续。

自制序列帧：把等大的格子从左到右、从上到下排进 `fx/sheet.png`，在插件的 assets 对象或 assets.json 写：

```json
{"fx":{"flipbooks":{"flash":{"image":"fx/sheet.png","frames":8,"cols":4,"fps":16,
  "anchor":[0.5,0.5],"scale":1,"blend":"add","loop":false}},
  "bind":{"char_x_my_pack_guard":{"0":{"skillStart":"flash","hit":"flash"}}}}}
```

把 `my_pack` 换成自己的插件命名空间。每个技能可绑定 skillStart、skillLoop、skillEnd、attack、hit、projectile。
[ASSUMED] skillLoop 跟随干员直到技能结束或死亡；弹道按通用弹道速度飞向目标，抵达时播 hit。
[ASSUMED] 远程伤害事件没有来源 id，因此预估抵达效果不抢占目标的伤害火花；只有已识别来源且实际播出 hit 时才替代本次火花。
射手或目标死亡会取消待播命中，其他攻击者和躯壳计次伤害继续正常显示。
序列帧在 2D 和 3D 都显示；「官方特效」关闭时隐藏，暂停时也暂停。
同一个内容插件自带 assets 时，DSL 可以写 `{"fx":{"kind":"plugin","id":"flash","at":"self","dur":0.4}}`。
另一个外观插件应使用 bind；DSL 不跨插件找同名效果 [ASSUMED]。

已有编译工具的作者可在 fx 中加 `"index":"fx/index.json"`，提供本项目 fx-index v3 / fx-prefab v1 的受限子集。
只支持粒子、内置 Quad 和内置粒子材质；不支持脚本、自定义着色器、外部 URL、自定义网格、动画剪辑和效果链。
浏览器准备和合并素材时会再次校验单位归属及预制体内容；非法包不参与合并。切换素材组或销毁回放会释放序列帧底层贴图。
编译特效仍仅显示在 3D。[ASSUMED] 每包 256 文件 / 32 MiB，单 JSON 1 MiB，JSON 总共 4 MiB；
贴图仅接受 8 位 RGB/RGBA PNG，宽高最多 2048；序列帧最多 256 帧、60 fps；粒子上限等完整规则见
[PLUGINS.md 的 Operator effects](PLUGINS.md#operator-effects-031)。这些限制是本项目的资源预算，不是官方数值。

保存文件后，在 `/studio/` 选择插件 →「试一场」→「单干员对木桩」→「优先使用插件的新干员」→「开始对照」。
检查技能开始 / 持续 / 结束、普攻、命中、弹道，再切「画面」的 2d / 3d 和「官方特效」的关闭 / 精简 / 完整。
切换会从头回放；暂停和重新播放不应留下旧效果。官方映射需先提取素材；特效引用缺失会回退，格式错误会拒绝加载。
独立的 `/studio/console.html` 仍只测试原版干员，可用来观察被借用的官方干员作对照。
Forge 的 `fx.silentPhases` 会变成外观插件的同名声明，只取消该 phase 的通用光效，不取消模型形态变化。
### 房间规则开关（0.3.1）

只改规则也能做成 content 插件，不需要虚假的数据补丁或权限。在 plugin.json 写例如
`"rules": { "prepLoadout": "prep", "unequip": "allow" }`，由房主选择插件后生效。
房间的插件标签、列表和对局角落会用文字显示当前规则；浏览器自己不能开启。

| 开关 | 默认 | 可选 |
| --- | --- | --- |
| shopBias | official：官方抽取 | bondBias：商店装备偏向本玩家已激活盟约的 giveBondId，阶级与库存限制照旧；同阶级没有候选就回落，不直接授予盟约，也不额外偏向核心盟约或骑士戒律 |
| prepLoadout | locked：简报后锁定 | prep：休整期、未准备时可打开干员调配；复用 room.loadout，只覆盖提交点名的干员，明确的默认值表示恢复默认，其他人保留；简报仍整份替换 |
| morphPairing | official：同构体占格，配对所有其他盟约装备 | plus：同构体不占格，每人一件，只配对装备行最左边的盟约装备；两格普通装备仍在，替换不会销毁同构体 |
| unequip | official：无法卸下 | allow：休整期未准备时，干员的装备详情有「卸下」；先退回手牌最右空位，再进临时区；都满则 HAND_FULL，装备不动；机器人不会卸下 |

未知开关、选项或外观/界面/语言插件声明 rules 会报 PLUGIN_RULES。两插件把同一个开关设成不同选项，
报 PLUGIN_RULE_CONFLICT 并点名双方；同选项可以重复。显式写默认值也参与冲突检查和内容哈希。
不写 rules 不增加哈希字段；[ASSUMED] 空对象等同没写。脚本类也可声明，但仍须通过原有脚本许可闸门 [ASSUMED]。
[ASSUMED] prep 提交里的潜能/练度也按干员合并；选同构体作为替换对象时改换最左普通装备；第二件同构体报 BAD_TARGET；
卸下沿用准备后的操作锁，只认临时区可见的五格，不把隐藏溢出当空位。回收会归还全部装备，不需要检查装备格。

休整期调配通过校验后，会按新技能/模组核对受影响干员在棋盘、手牌和临时区的召唤物，移除过期或超量卡片，
补足缺少的卡片，再重算射程与状态。[ASSUMED] 优先保留棋盘阅读顺序中的有效召唤物，再按手牌、临时区下标保留；
补发沿用手牌优先、临时区可溢出的队列。删除临时卡也删除其到期记录。没改调配、没被点名的干员不会补回已消耗卡；校验失败不改状态。

Forge 导入会把 behaviour 的四个开关转成 rules，自动成为玩法插件，支持只有开关的包；未知项逐条跳过并说明。
option 可以省略：省略表示明确选择该开关的默认项，仍进入哈希和冲突检查；显式 null、非字符串或未知选项仍跳过。
重复且选项不同则保留第一条 [ASSUMED]。本项不导入公告。完整定义见 [PLUGINS.md](PLUGINS.md#rule-switches)。

## 声明式交互窗口（0.3.1，PR #682）

JSON Schema 与清单读取器共同校验示例，检查路径、API、类别、权限及对应内容。只有本插件内的 JSON 数组或

每栏的 `available` 随当前库存和玩家记录更新；不可用卡显示提示并禁用选择，仍可使用剩余刷新次数。
`effect` 和 `shared` 尚不支持，检查时拒绝；`options.tiers` 会警告不读取。
