## §28.12 浏览器验收退出时释放自有日志管道

完整浏览器验收中，真实对局与观战的断言已经全部通过，但 Chrome 的崩溃报告/更新辅助进程继承了日志管道，测试进程仍在等待读取结束。共用测试客户端现在在浏览器子进程明确退出后释放它的 stdio；关闭失败、子进程仍活着时不关闭管道，也不操作其他浏览器进程。游戏运行时代码与战斗规则不变。

新增真实子进程继承 stderr 的回归，以及关闭失败/信号退出的边界检查；验收要求原异常文件单独重跑并确认正常结束。首轮异常与复测结果分别保留在本轮验收记录中。

同一轮的版本重连测试在刻意停服时，Chrome 可能报告连接拒绝、连接重置或未连接的 socket。测试只在主动停服至恢复握手的窗口内排除这些已知传输日志；正常运行期间仍检查它们，脚本异常始终保留，所有版本指纹、重连及换局刷新断言不变。

### 28.24 Echo / counter recursion found by the cooperative benchmark

The 40-seed benchmark exposed existing hook-depth errors in co-op seeds 3 and 29, plus seed 14 after the purchasing
change. In all three, “余音” damage pulses and 刺玫 / 泡泡 counters synchronously called each other. A scaled echo can
have 67 hit-count HP; the generic 32-hook guard cut off effects before the legitimate chain finished. The same chain

### 28.27 Cabin capacity and local recovery races — #431

- **Observed:** 克莱门莎 S2 removed the carry buff from dead, hidden, uncarryable or unreachable passengers but
  retained them in the passenger list and weight budget. Two weight-3 riders blocked a replacement after one died;
  a dead zero-weight rider still occupied one of the 15 slots; a dead weight-4 rider retained four budget points.
- **Now:** after moving the cabin, release invalid passengers and return each one's current weight before either
  boarding limit is checked that tick. Remaining passengers keep their order and movement. This corrects bookkeeping
  under the existing S2 rules and official blackboard limits (sources in §28.1); no new gameplay assumption is added.
- **Observed (#431):** a recovery attempt with a smaller tab id could claim a token while its owner was refreshing
  or still initializing. The original page then fell back to another recent identity, or erased its own token.
- **Now:** startup with a session token chooses only that token or null and answers ownership queries immediately.
  The first server welcome for a token stamps its ownership; reload/reconnect preserves that stamp. Earlier welcome
  wins a conflict, a live document wins an equal-stamp duplicate, and tab id resolves remaining ties. Explicit recovery
  keeps its choice only in memory and reconnects in the same document; only welcome persists it. An original owner
  returning cancels the lower-priority choice, including a later welcomed holder's reconnect. Nicknames and IPs remain
  irrelevant to identity; a refused recovery retains the previous nickname until its own welcome.
- **In-flight handshake:** a hello can reach the server after another connection's welcome. Optional `hello.noReplace`
  makes shared candidates refuse a currently connected seat; `hello.claimAt` lets the server refuse an established
  holder with a later welcome stamp. Refusal is `SESSION_IN_USE`, before rebinding or closing the incumbent socket.
  Normal same-stamp reconnects and older clients remain accepted. These are local ownership hints, not authentication;
  the bearer token remains the authority. A revoked hello's stale welcome is ignored before going online, flushing
  queued actions or notifying listeners, and retries use a new socket. Reconnect-window duration is unchanged.
- **Regression coverage:** `op_clemnt.test.js` adds same-tick replacement for death / hidden / self-bound /
  teleport immunity / failed path, the 15-slot and weight-4 probes, and a changed current weight. The eight regressions
  fail before the fix and pass after it. `client-static.test.js` covers live / reload / mid-init, no fallback identity,
  welcome-only persistence, earlier-welcome priority and a welcome arriving during init. The real-browser recovery
  test holds a refreshing owner's initialization open while another page clicks recovery and checks both server
  identities and live sockets; closed-window recovery also checks that welcome arrives without a page reload.
  `client-identity-handshake.test.js` controls delayed hellos / welcomes through the real client and server handlers,
  including a later holder's buffered reconnect, same-stamp reconnect, stale-welcome action suppression and validation.
